# Dictionarium Sinicum: Building a 428K-Headword Chinese Dictionary in 12 Languages with a Single LLM for Under $100

## Abstract

We present *Dictionarium Sinicum*, an open multilingual Chinese dictionary comprising 428,073 headwords with definitions in 18 languages, constructed by merging seven community-maintained dictionaries with glosses generated by a single LLM (MiniMax M2.5) at a total API inference cost of approximately \$100, excluding developer time. A three-phase pipeline — batch translation, retry, and context-aware backfill — achieves 100% coverage across all 7.7M headword-language slots. We describe prompt engineering techniques that prevent script contamination in CJK-target languages, including Japanese kanji echo and Korean hanja mixing, and a deterministic post-translation script validator that detects and rejects cross-language contamination (Cyrillic in Arabic, Hangul in Japanese, Latin in Persian, etc.) at a rate of 0.83% of all generated definitions. Automated comparison against four community reference dictionaries over 453 headword-language pairs shows 87.3% sense coverage with a 12.5% false sense rate. The dictionary, augmented with 511K Cantonese and Hokkien dialect forms from 18 open sources, is released under CC BY-SA 4.0.

## 1. Introduction

Bilingual and multilingual dictionaries remain essential infrastructure for language learning, translation, and NLP. For Chinese, the open-source community has produced high-quality dictionaries for a handful of language pairs — CC-CEDICT for English (~124K entries), HanDeDict for German (~159K entries), CFDICT for French (~56K entries), and CC-CIDICT for Indonesian (~124K entries) — but no comparable resources exist for Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, or Swedish. Creating such dictionaries manually requires years of expert effort per language pair.

Recent advances in large language models (LLMs) suggest an alternative: using a single multilingual model to generate dictionary-quality definitions at scale. However, prior work on LLM-assisted lexicography has been limited to small-scale experiments. The closest precedent is a Pre-Qin philosophy lexicon project using Qwen3-14B to generate bilingual dictionary entries for approximately 1,000 classical Chinese philosophical terms in a single language pair (npj Heritage Science, 2026). Lu et al. (EMNLP 2024) use existing bilingual dictionaries as chain-of-thought context to improve LLM translation, but this work uses dictionaries to help LLMs translate text, not to generate new dictionary entries. No published work has attempted dictionary generation at the scale of hundreds of thousands of headwords across more than two target languages.

We address this gap with *Dictionarium Sinicum*, a system that:

1. **Merges** seven community-maintained Chinese dictionaries (CC-CEDICT, HanDeDict, CFDICT, CC-CIDICT, CHEDICC, Wiktextract, JMdict) covering 6 language pairs into a unified headword table of 428,073 entries.
2. **Translates** all headwords into 18 languages using a single LLM (MiniMax M2.5) with carefully engineered prompts that produce dictionary-style output and prevent script contamination.
3. **Backfills** gaps using a context-aware prompt that sends existing translations as read-only context, ensuring consistency across languages.
4. **Augments** the dictionary with 511,514 dialect forms from 18 open sources covering Cantonese (Jyutping, 99.9% single-character coverage) and Hokkien (POJ/Tâi-lô) pronunciations and lexical equivalents.

The total inference cost was approximately $100, and the full pipeline was completed in under one week. The project's name honors the *Dictionario Hispanico Sinicum* (1626-1642), a 27,000-entry Spanish-Chinese-Hokkien dictionary compiled by Dominican missionaries in Manila — a reminder that multilingual Chinese lexicography has a four-century history, and that the Hokkien maritime vocabulary in our dialect data traces the same trade routes documented in that manuscript.

## 2. Related Work

### 2.1 Multilingual Lexical Resources

Large-scale multilingual lexical resources have been constructed through both manual and automated methods. PanLex (Kamholz et al., 2014) aggregates bilingual dictionaries into a graph covering ~5,700 languages with over 1.2 billion pairwise translations, but its Chinese coverage is limited to headword-level mappings without definition glosses. BabelNet (Navigli and Ponzetto, 2012) combines WordNet, Wikipedia, and other resources into a multilingual encyclopedic dictionary, but is not open-access for bulk redistribution and focuses on synset alignment rather than dictionary-style glosses. Our work differs from both in producing complete, human-readable definition glosses (not just translation equivalents or synset links) for a single source language across 18 targets, released under CC BY-SA 4.0.

### 2.2 LLM-Assisted Lexicography

The use of LLMs for dictionary construction is an emerging area with limited published work. The closest precedent is a Pre-Qin philosophy lexicon (npj Heritage Science, 2026) that uses Qwen3-14B to generate ~1,000 bilingual entries for classical Chinese philosophical terms — two orders of magnitude smaller than our work. Chain-of-Dictionary prompting (Lu et al., EMNLP 2024) uses existing bilingual dictionaries as chain-of-thought context to improve LLM translation of rare words — a complementary approach where dictionaries help LLMs translate, whereas we use LLMs to *build* dictionaries.

### 2.3 Multilingual Translation Models

General-purpose multilingual translation models such as NLLB (Costa-jussà et al., 2022) cover 200+ languages but are designed for sentence-level translation, not dictionary-style glosses. Tower (Alves et al., 2024) focuses on high-resource language pairs. Neither has been evaluated for or applied to dictionary construction. These models are designed for sentence-level translation and do not natively produce multi-sense gloss lists, making direct comparison nontrivial (see Limitations).

### 2.4 Community Chinese Dictionaries

The open Chinese dictionary ecosystem is built on the CC-CEDICT model: community-maintained, CEDICT-format text files released under Creative Commons licenses. CC-CEDICT (English, CC BY-SA 4.0, ~124K entries), HanDeDict (German, CC BY-SA 3.0, ~159K entries), CFDICT (French, CC BY-SA 3.0, ~56K entries), and CC-CIDICT (Indonesian, CC BY-SA 4.0, ~124K entries) together cover four European languages and Indonesian. Wiktextract provides multilingual glosses extracted from Wiktionary, and JMdict covers Japanese. No comparable community dictionaries exist for Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, or Swedish.

## 4. Translation Pipeline

### 4.1 Model Selection

We evaluated 20+ LLMs across 10 inference providers (Table 2) on a 5-headword test suite covering emergency service numbers (culturally specific), anime titles (transliteration challenges), and medical terminology. Selection criteria were:

1. **Correct 18-language output** in the prescribed `xx: def1/def2` format
2. **No script contamination** (Chinese characters leaking into non-CJK definitions)
3. **Geographic context preservation** (e.g., "Mainland China and Taiwan" for 110)
4. **Sustainable throughput** at the scale of 428K headwords
5. **Cost** under $200 for the complete run

| Model | Provider | Time/entry | Output Issues | Est. Cost |
|-------|----------|-----------|---------------|-----------|
| MiniMax M2.5 | MiniMax API | 1.2s | None | **$93** |
| Kimi K2 Instruct | Groq | 1.8s | None | $246 |
| Nemotron Ultra 253B | NVIDIA NIM | 7.0s | None | Credits only |
| Claude Sonnet 4.6 | Anthropic | 19.8s | Headword echo | $1,124 |
| DeepSeek V3.2 | NVIDIA NIM | 35.3s | Headword echo | N/A |

| MiniMax M2.1 | Fireworks | 5.4s | None | $93 |

MiniMax M2.5 was selected for production: zero issues on the test suite, 1.2s/entry throughput, no observed rate limits with 20 parallel workers, and an estimated cost of $93 for the full run.

A notable finding from this evaluation is that the same open-weight model can produce dramatically different output depending on the inference provider. MiniMax M2.1 served by NVIDIA NIM took 167s per entry with thinking mode silently enabled, while the same weights on Fireworks took 5.4s with thinking disabled. Llama 4 Maverick echoed raw headwords on NIM but produced clean output on SambaNova, suggesting different quantization or prompt preprocessing. Benchmark scores (SWE-bench, MMLU) showed no predictive value for this structured multilingual task: DeepSeek V3.2 (SWE-bench 73.1%) echoed headwords, while MiniMax M2.5 (unranked) produced flawless output. A systematic study of these cross-provider divergences is beyond the scope of this paper, but our observations align with emerging evidence that inference acceleration introduces unpredictable behavioral changes (Kirsten et al., NAACL 2025).

### 4.2 Prompt Engineering

The production prompt generates all 18 languages simultaneously for each batch of 20 headwords. Key design decisions:

**System prompt** (176 tokens): Establishes the lexicographer persona, output format (`xx: def1/def2`), conciseness constraints (max 5 glosses), and language-specific rules addressing three classes of script contamination:

1. **Japanese kanji echo**: Without explicit instruction, LLMs frequently "define" a Chinese word in Japanese by simply repeating the same characters (e.g., 銀行 → 銀行). The prompt requires: *"Provide the MEANING in Japanese, not just kanji echo or kana reading. Write a Japanese definition/gloss that explains the word."*

2. **Korean hanja mixing**: Korean definitions often include Chinese characters (hanja) that would be unrecognizable to most modern Korean readers. The prompt specifies: *"Write in Hangul only. Do NOT mix in Chinese characters (漢字/한자)."*

3. **General CJK leakage**: A blanket prohibition: *"Every non-Chinese definition must contain ZERO Chinese characters (汉字)."*

**User prompt** (batch of 20): Each entry includes traditional/simplified characters, pinyin, POS tag, all existing community definitions as context, and 1-2 example sentences drawn from our 113M-chunk Chinese corpus (zhcorpus). For headwords with CC-CEDICT, HanDeDict, CFDICT, or CC-CIDICT entries, the model sees those definitions to ground its output. The corpus examples — sourced from Chinese Wikipedia, Baidu Baike, THUCNews, and news2016zh — provide real-world usage context that helps disambiguate polysemous headwords and ground definitions in attested usage rather than the model's parametric knowledge alone. Example sentences are retrieved via unranked FTS5 lookup (<15ms per headword), filtered to prefer 20-100 character chunks, and formatted as a separate "Example sentences:" block between the existing definitions and the language placeholders. This constitutes **pivot translation**: for the six languages without community dictionaries (Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, Swedish), the model effectively translates from the English and other community-language glosses rather than directly from Chinese. We accept this trade-off because the alternative — generating all 12 languages without any context — produces lower-quality output with more script contamination and sense drift. The prompt concludes with explicit `xx:` placeholders for all 12 target languages.

**Token economics**: ~5,700 tokens per batch (500 system + 2,200 input including examples + 3,000 output). Full run: 21,403 batches.

### 4.3 Three-Phase Execution

| Phase | Description | Entries | Definitions | Time | Rate | Cost |
|-------|-------------|---------|------------|------|------|------|
| 1. Main run | Full 18-language translation | 374,602 | 4,410,579 | ~24h | 4.6/s | ~$93 |
| 2. Retry | Zero-def headwords from phase 1 | 53,471 | 616,276 | 92min | 5.4/s | ~$3 |
| 3. Backfill | Partial-coverage headwords | 82,550+ | 110,345+ | ~105min | 8-14/s | ~$4 |
| **Total** | | **428,073** | **7,697,901** (minimax) | ~27h | | **~$100** |

**Phase 1** processed all 428,073 headwords in batches of 20 with 20 parallel workers. The API returned unparseable responses for 53,471 headwords (12.5%), primarily due to batch-level formatting errors where the model's response was cut off or malformed.

**Phase 2** retried the failed headwords using the same prompt and pipeline, recovering 616,276 additional definitions and leaving 5,875 headwords with partial coverage (< 18 languages).

**Phase 3** used a distinct context-aware backfill prompt (`backfill_langs.py`) that sends all existing translations as read-only context, asking the model to produce *only* the missing languages. This design ensures consistency: the model sees "en: bank / de: Bank / fr: banque" and produces a Spanish definition that matches in style and specificity. Three backfill passes on 2026-03-07 closed all remaining gaps, achieving 100.0% coverage across all 428,073 × 12 = 5,136,876 language slots.

### 4.4 Parser Robustness

Parsing structured LLM output at scale required handling several failure modes:

- **Multi-language line collapse**: The model sometimes outputs `en: bank/de: Bank/fr: banque` on a single line. A regex-based normalizer splits on `/xx:` boundaries where `xx` is a known language code.
- **Numbered vs unnumbered responses**: The backfill prompt, which often requests a single language per entry, causes the model to drop entry numbers. The parser detects this and uses blank lines as entry separators.
- **Overwrite protection**: Three layers prevent backfill from corrupting existing data: (1) query filter returns only headwords with < 18 languages, (2) parser only accepts languages listed in the missing set, (3) database existence check before every write.

## 5. Quality Assessment

### 5.1 Script Contamination Audit

A full-corpus audit of all 7.7M minimax definitions using a deterministic script validator revealed 63,712 definitions (0.83%) containing scripts that do not belong to the target language. This goes beyond CJK leakage: the dominant contamination mode is **cross-language script mixing**, where the model inserts words from a different language mid-definition.

**Table 6: Script contamination by target language (full corpus)**

| Language | Contaminated | Rate | Primary Contamination |
|----------|-------------|------|----------------------|
| Arabic | 16,739 | 3.91% | Latin words (9,692), CJK (6,119), Cyrillic (1,565) |
| Persian | 7,284 | 1.70% | Latin words (4,539), CJK (2,285), Cyrillic (782) |
| Japanese | 4,939 | 1.15% | Hangul (3,050), Cyrillic (1,765) |
| Hindi | 3,725 | 0.87% | CJK (3,007), Arabic (387), Cyrillic (251) |
| Indonesian | 2,815 | 0.66% | CJK (2,250), Cyrillic (464) |
| Korean | 2,397 | 0.56% | Kana (1,376), Cyrillic (739) |
| Other 12 langs | 25,813 | 0.34–0.58% | CJK (dominant), Cyrillic (secondary) |

**Post-cleanup status.** After applying the three-stage cleanup pipeline to all contaminated definitions and running multiple backfill passes with the integrated validator, the dictionary achieved the following completeness:

- **Multi-character headwords** (397,527): 100.0% complete across all 18 languages — zero gaps.
- **Single-character headwords** (30,546): 27,681 (90.6%) complete across all 18 languages; 2,865 (9.4%) have residual gaps in 1–6 languages, concentrated in Arabic (1,084 gaps), Thai (1,016), Persian (658), and Hindi (301). These gaps persist because the affected headwords are obscure radicals and rare components whose definitions inherently require citing Chinese characters, which the validator correctly rejects. The remaining gaps do not affect any HSK-listed characters — all primary readings of all HSK 3.0 characters have complete 18-language coverage.

The contamination is uniformly distributed across headword ID ranges (~0.3–0.6% per 10K block), indicating a systematic model tendency rather than a batch-level failure. 98.6% of contaminated definitions were produced by the `v2-backfill` prompt version (Phase 3), with the `v4-backfill` variant showing a slightly *higher* contamination rate (0.52% vs. 0.36%), confirming that prompt engineering alone does not prevent the problem.

**Contamination taxonomy.** We identified five distinct contamination modes:

1. **Cyrillic-in-non-Cyrillic** (~10K definitions): The model falls back to Russian when translating into less-resourced scripts. Example: Arabic definition for 一世 → "жизнь واحدة/كل الحياة" (Russian "жизнь" = life mixed with Arabic). Entire definitions are sometimes produced in the wrong language (三项全能 → "триатлон" instead of Arabic).

2. **Hangul-in-Japanese / Kana-in-Korean** (~4.4K definitions): Systematic confusion between CJK languages. 3,050 Japanese entries use Korean 異体자 instead of Japanese 異体字. 1,376 Korean entries contain Japanese katakana (세피스ーツ instead of 세피스수트).

3. **Latin-in-Arabic/Persian** (~14K definitions): English, French, or German words injected into Arabic/Persian definitions. After exempting proper names, scientific binomials, and universal acronyms (USB, DNA), ~14K definitions contain genuine Latin-script contamination (e.g., "ينتشر كال wildfire", "تي شIRT").

4. **CJK-in-non-CJK** (~40K definitions): Chinese characters in definitions for languages that should not contain them. After exempting metalinguistic cross-references ("variant of 迥", "Variante von 平成" — detected via multilingual reference-frame patterns across all 18 target languages), approximately 40K definitions contain genuine CJK leakage.

5. **Multi-language field dumps** (rare but severe): The model occasionally writes definitions for multiple languages into a single field (Arabic definition containing "| hi: भोज का अंत | it: fine del banchetto").

**Cleanup methodology.** We implemented a three-stage cleanup pipeline:

1. **Deterministic script validator** (`script_validator.py`): For each definition, detects all Unicode script families present and compares against a per-language allowlist. CJK characters are exempted when they appear inside metalinguistic reference frames, detected via compiled regex patterns covering all 18 target languages (e.g., English "variant of", Japanese "の異体字", Korean "의 이체자", Arabic "واریانت"). Latin characters in Arabic/Persian are exempted when they constitute single letters, scientific binomials (*Genus species*), proper names (initial capital), or universal acronyms (all-caps, 2–6 characters).

2. **Delete contaminated definitions**: Only minimax-sourced definitions are deleted; community dictionary entries are never touched. This creates gaps in the headword-language coverage matrix.

3. **Context-aware re-translation**: The existing backfill pipeline (`backfill_langs.py`) detects gaps and re-translates them, sending all remaining *clean* definitions for each headword as context to ensure semantic consistency. The script validator is now integrated as a hard reject gate — contaminated output is discarded before database write, and the gap persists for the next backfill pass.

This pipeline was applied to all 63,712 contaminated definitions. The validator is permanently integrated into the translation pipeline to prevent future contamination.

### 5.2 Comparison with Community Dictionaries

For the four languages with existing community dictionaries that provide glosses (English, German, French, Indonesian), we compared LLM-generated definitions against human-curated references. JMdict was excluded because it stores kana readings rather than Japanese-language glosses, making gloss-level comparison impossible. We sampled 200 headwords stratified by community source coverage as a frequency proxy (high: defined in 4+ sources, mid: 3, low: 2, rare: 1) and measured two metrics across 453 headword-language pairs:

1. **Sense coverage**: proportion of reference senses captured by the LLM gloss (automated lexical overlap with 50% word-overlap threshold)
2. **False sense rate**: proportion of LLM glosses not matched by any reference sense

**Important caveat**: The translation prompt provides all existing community definitions as input context (Section 4.2). For these four languages, the model *sees* the reference glosses and is asked to produce output in the same language. This comparison therefore measures **context utilization** — how faithfully the model preserves reference senses — not independent translation quality. We find that 42% of English, 40% of German, 55% of French, and 60% of Indonesian LLM glosses are substring matches of the corresponding community definition. This is by design: for languages with community dictionaries, we *want* the model to preserve established glosses rather than inventing alternatives. The evaluation quantifies the residual divergence.

**Table 3: LLM vs Community Dictionary Comparison by Language**

| Language | Reference | n | Sense Coverage | False Sense Rate |
|----------|-----------|---|---------------|-----------------|
| English | CC-CEDICT | 139 | 85.8% | 14.1% |
| German | HanDeDict | 105 | 87.9% | 17.9% |
| French | CFDICT | 70 | 81.2% | 18.6% |
| Indonesian | CC-CIDICT | 139 | 91.3% | 3.7% |
| **Overall** | | **453** | **87.3%** | **12.5%** |

**Table 4: Comparison by Frequency Band**

| Band | n | Sense Coverage | False Sense Rate |
|------|---|---------------|-----------------|
| high (4+ sources) | 190 | 84.7% | 16.7% |
| mid (3 sources) | 146 | 87.4% | 11.8% |
| low (2 sources) | 94 | 90.8% | 5.7% |
| rare (1 source) | 23 | 93.5% | 10.9% |

The overall sense coverage of 87.3% (95% bootstrap CI: [84.7%, 89.8%]) with a false sense rate of 12.5% (95% CI: [10.1%, 15.0%]) shows that the model successfully preserves most reference senses while introducing few unsupported glosses. Manual inspection reveals that most "false senses" are legitimate synonyms absent from the reference (e.g., "embankment" for 堤坝 is a valid translation not listed in CC-CEDICT).

The main failure mode is **sense compression**: the LLM produces fewer glosses than community dictionaries (median 2 vs 3), preferring the most common translation equivalent and omitting specialized or archaic senses. For example, 客栈 is glossed as just "inn" by MiniMax, while CC-CEDICT lists "tavern / guest house / inn / hotel." This pattern raises a linguistically interesting question: does the model compress senses uniformly, or does it systematically drop certain sense types (archaic, domain-specific, colloquial)? Preliminary inspection suggests the latter — archaic and register-marked senses are dropped preferentially — but a controlled study with sense-type annotation is needed to confirm this. Such a study would contribute to our understanding of how LLMs internalize and reproduce lexical polysemy structure.

Manual inspection of the 57 headword-language pairs with sense coverage below 50% reveals six failure categories:

| Failure Type | Frequency | Example |
|-------------|-----------|---------|
| **Sense compression** | 38% | 客栈: "inn" vs "tavern / guest house / inn / hotel" |
| **Register shift** | 22% | Archaic/literary senses dropped; colloquial preferred |
| **Synonym substitution** | 18% | Valid translations not matching reference wording |
| **Cross-reference loss** | 12% | "variant of X" entries lose the reference form |
| **Domain narrowing** | 7% | Technical/specialized senses omitted |
| **Genuine error** | 3% | Wrong meaning or confused with homograph |

The dominant pattern — sense compression and register shift — suggests the model preferentially retains high-frequency translation equivalents and discards specialized, archaic, or register-marked senses. Genuine errors (wrong meaning) account for only 3% of low-coverage pairs.

For the six languages *without* community dictionaries (Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, Swedish), the model relies on the English and other community-language context as a pivot. We have no external reference for these languages and cannot make quality claims about them.

### 5.3 Source Priority and Definition Merging

For headwords with definitions from multiple sources, we apply a priority hierarchy: community dictionaries (CC-CEDICT, HanDeDict, CFDICT, CC-CIDICT, JMdict) > Wiktextract > MiniMax. This ensures that human-curated definitions take precedence, with LLM translations filling gaps for languages without community dictionaries (Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, Swedish).

## 6. Downstream Application: Language Pack Generation

To validate the dictionary's practical utility, we built a language pack generator that produces consolidated SQLite databases for two Chinese learning applications: Copyworks (single-character entries, all 18 languages in one wide table) and iCE/Intuition (full dictionary, all 18 languages). The consolidated architecture replaces per-language database files with a single database containing one column per language, enabling column-scoped FTS4 search (e.g., `MATCH 'es:banco'`). The Copyworks database embeds character metadata (strokes, radicals, HSK 3.0 levels, Cantonese/Hokkien pronunciations, lesson content) alongside all 18 language definitions, eliminating the need for separate chardata files at runtime. Databases are encrypted with CEROD for distribution. The dictionary is currently deployed in production for English and Spanish, with all 18 languages shipping in the next release.

## 7. Limitations

**Glosses, not definitions.** The resource produces translation equivalents (glosses), not full lexicographic definitions with usage notes, example sentences, grammatical patterns, or register markers. Entries lack sense discrimination: a polysemous word like 打 produces a flat list ("golpear / jugar / hacer" in Spanish) without indicating which target-language verb corresponds to which Chinese sense. For inflecting target languages, bare citation forms lack grammatical metadata (German noun gender, Russian aspect pairs). The resource is best understood as a multilingual gloss list in the tradition of CC-CEDICT, not a professional dictionary in the sense of the *Oxford Chinese Dictionary*.

**Evaluation limitations.** The 87.3% sense coverage figure is an automated lexical overlap proxy, not a human judgment, and the evaluation is partially circular: the model sees community definitions as input context (Section 5.2). For the six languages without community references (Spanish, Korean, Russian, Vietnamese, Tagalog, Persian, Swedish), we have no external quality measure at all. Comparison against MT baselines (NLLB, Google Translate) remains future work.

**Pivot translation bias.** All translations are mediated through community-language context (primarily English), inheriting English sense boundaries. Where English conflates two Chinese meanings, all target languages will too. The LLM may partially bypass this via its multilingual training, but direct Chinese→target evaluation is needed to quantify the effect.

**Single-model homogeneity.** All 5.1M LLM-generated glosses originate from a single model (MiniMax M2.5) on a single commercial API. Model-specific biases in translation style, sense selection, and cultural framing propagate uniformly. The pipeline's reproducibility depends on this API remaining available.

**Headword and language selection.** The 428K headwords are inherited from CC-CEDICT without curation; the inventory includes phone numbers, anime titles, and proper nouns alongside common vocabulary. The 18 target languages (en, de, fr, es, sv, ja, ko, ru, id, vi, tl, fa, nl, pt, ar, th, hi, it) cover major language families but omit Malay, Bengali, and Swahili — languages with significant Chinese-speaking diaspora or trade communities.

**No interchange format.** The resource is stored as flat text in SQLite without compliance with TEI-Lex-0, OntoLex-Lemon, or ISO 24613 LMF, limiting interoperability with existing dictionary infrastructure.

## 8. Future Work

**From glossary to dictionary.** The most immediate next step is sense-discriminated entries — mapping each target-language gloss to a specific Chinese sense with usage guidance — combined with grammatical enrichment (German noun gender, Russian aspect pairs). This would yield the first open, sense-structured multilingual Chinese dictionary.

**Computational loanword detection.** The dictionary contains both Hokkien source forms and Southeast Asian target languages in a single resource — infrastructure for tracing lexical diffusion at scale. Linking Hokkien *tāu-hū* to Indonesian *tahu*, Tagalog *taho*, and Thai เต้าหู้ would produce a machine-readable atlas of Chinese vocabulary diffusion across maritime Southeast Asia.

**Under-resourced languages and community evaluation.** The ~$100 cost makes the pipeline relevant for languages without institutional support for manual lexicography. Native-speaker evaluation across all 18 target languages would establish ground-truth quality metrics and generate training data for automatic quality estimation.

## 9. Conclusion

We have demonstrated that a single commercial LLM can produce a multilingual Chinese glossary of unprecedented scale — 428,073 headwords in 18 languages, totaling 7.7M LLM-generated definitions — for approximately $100 in API inference costs, excluding developer time for prompt engineering, model evaluation, and pipeline development. The key enablers are (1) batched prompting that generates all languages simultaneously, (2) language-specific prompt rules that reduce script contamination, (3) a deterministic post-translation validator that rejects the ~0.83% of definitions where the model mixes scripts, and (4) a context-aware backfill pipeline that achieves 100% multi-character coverage and 90.6% single-character coverage (with residual gaps limited to obscure radicals in Arabic/Thai/Persian/Hindi). The resulting resource, combined with community dictionaries and 511K dialect forms spanning Cantonese and Hokkien, provides the first open multilingual Chinese lexical resource covering major languages of Europe, East Asia, Southeast Asia, and the Middle East.

The resource is a beginning, not an endpoint. Transforming gloss lists into sense-structured, grammatically enriched, human-validated dictionary entries — and extending the approach to under-resourced languages where the need is greatest — is a multiyear research program requiring expertise in computational lexicography, multilingual NLP, lexical typology, and community-based language documentation. The scientific questions this work opens — How do LLMs represent cross-lingual lexical semantics? Does pivot translation reproduce or restructure sense boundaries? Can computational methods trace historical loanword diffusion across language families? — are as valuable as the artifact itself. We release the complete resource, build tools, and evaluation data at [repository URL] under CC BY-SA 4.0, and invite the community to build upon it.

## Appendix A: Prompt Templates

### A.1 System Prompt (v2, production)

```
You are a professional multilingual Chinese lexicographer producing
dictionary-style definitions in 18 languages.

Rules:
- Output EXACTLY one line per language in format "xx: def1/def2"
- Be concise: dictionary style, not full sentences
- Use the target language exclusively for each definition
- For verbs, start with the infinitive form appropriate to the target language
- For nouns, give the most common equivalent(s)
- Maximum 5 glosses per entry
- No explanatory notes, no parenthetical qualifiers unless essential

CRITICAL: Every non-Chinese definition must contain ZERO Chinese
characters (汉字).

Language-specific rules:
- ja: Provide the MEANING in Japanese, not just kanji echo or kana
  reading. Write a Japanese definition/gloss that explains the word.
  Use native Japanese vocabulary.
- ko: Write in Hangul only. Do NOT mix in Chinese characters (漢字/한자).
- tl: Use natural Tagalog vocabulary. Do NOT produce literal
  word-for-word translations from English.
- fa: Write definitions in Persian script. Use native Persian vocabulary.
- vi: Write in Vietnamese with proper diacritics. Do NOT include
  Chinese characters.
```

### A.2 User Prompt (per-entry, with corpus examples)

```
Chinese: 銀行 / 银行

POS: noun

Existing definitions:

Produce definitions for each language below. Output EXACTLY one line

en:
de:
fr:
es:
...
```

Example sentences are retrieved from the 113M-chunk zhcorpus via FTS5 lookup (1-2 per headword, 20-100 characters preferred). The `--skip-corpus` flag disables this for faster runs without a local corpus database.
